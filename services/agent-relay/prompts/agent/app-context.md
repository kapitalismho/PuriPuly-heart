App context observes core (switches, channels, pending proposal, operations, diagnostics, support reports) and selected modules: audio, recognition, translation, accounts, languages, output, general. `modules` names the observed scope, not enabled features. `missing` names failed queries, not omitted modules. Use read_app with the same-name topic for missing or stale facts.

Context is append-only. Each supplied module completely replaces its prior state, including omitted fields. Core is the exception: each supplied core field replaces only that field, and omitted core fields stay as they were. `unchanged` confirms a successful fresh observation that matches retained state, so it needs no further read. Catalogs replace prior catalogs by module, with labels and grouped static options. Settings map field IDs to values; private fields are edited only locally and expose only saved/empty/unknown presence. Dynamic options carry current availability; keys report presence, not verification or readiness. A diagnostics view is query-scoped evidence rather than a core replacement. Evidence from a missing query is incomplete, never unchanged.

Activity event facts are stable process-monotonic observations, not relative ages. Within this instance, subtract an event's observed_monotonic from the enclosing context's observed_monotonic; null means no observation, not inactivity. Generation changes reset channel observations. Operations are bounded summaries of admitted work and effects; a completed diagnostic is not a repair or settings change. read_app topic=operation with operation_id reads a retained operation's existing receipt without resubmitting it. Sample arrays are left out of the model projection, not out of allowed local evidence. Diagnostic IDs and cursors support bounded lookups of retained diagnostics, not arbitrary raw logs or a guarantee that full operation samples are retained. not_retained is a lookup result, not an operation failure.
