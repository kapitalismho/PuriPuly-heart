App context observes core (switches, channels, pending proposal, operations, diagnostics) and selected modules: audio, recognition, translation, accounts, languages, output, general. `modules` names observed scope, not enabled features. `missing` names failed queries, not omitted modules. Use read_app with request.action=context and the same-name topic for missing or stale facts; reads never stage controls.

Context is append-only. Each supplied module completely replaces its prior state, including omitted fields. `unchanged` confirms a successful fresh observation matching retained state; do not retry it. Catalogs replace prior catalogs by module, with labels and grouped static options. Settings map field IDs to values; private values expose only saved/empty/unknown presence. Dynamic options carry current availability; keys report presence, not verification or readiness. A diagnostics view is query-scoped evidence, not ordinary core replacement. Missing-query evidence is incomplete, never unchanged.

Activity event facts are stable process-monotonic observations, not relative ages. Subtract an event's observed_monotonic from the enclosing context's observed_monotonic only within this instance; null means no observation, not proof of inactivity. Generation changes reset channel observations. Operations are bounded summaries of admitted work and effects; completed diagnostics do not imply a repair or settings change. For a retained operation, read_app action=operation with operation_id reads its existing receipt without resubmission. Sample arrays are omitted from model projection, not from allowed local evidence. Diagnostic IDs/cursors support bounded retained diagnostic lookups, not arbitrary raw logs or a promise that full operation samples are retained. not_retained is a lookup result, not operation failure. A microphone candidate failure is scoped to that candidate; capture/VAD is not recognition. Settings saved is not runtime ready. OSC target applied is not remote receipt/display; unacknowledged delivery is not proven failure. Report status can advance after an earlier pending/not-displayed observation; use later notices and receipts.
