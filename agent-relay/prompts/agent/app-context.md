App context observes core (switches, channels, pending card, operations, diagnostics) and selected modules: audio, recognition, translation, accounts, languages, output, general. `modules` names the observed scope, not enabled features; a module outside it is not absent or disabled. `missing` names failed queries, not omitted modules. Inspect a missing/stale module through its same-name `get_app_context` topic when needed.

Context is append-only. Each supplied module object completely replaces its earlier state, including removal of omitted fields. `unchanged` confirms a fresh observation matching that module's retained state; a read with status `unchanged` succeeded and needs no retry. Reuse the latest retained state for those modules. `catalogs[module]` supplies labels, descriptions and static options grouped by UI section; each supplied catalog replaces the earlier catalog for that module. Module `settings` maps field IDs to current values, `private` exposes only saved/empty/unknown presence, and `options` carries current device/host/GPU/extension choices and runtime availability. Catalog `options_from` references another field in the same module catalog; `empty_label` names the empty value. `keys` contains saved booleans; `verification` lists only checked providers. A diagnostics `view` is query-scoped evidence, not a replacement for ordinary core state. Missing-query evidence is incomplete, never unchanged.
