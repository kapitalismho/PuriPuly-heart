## Owner amendment: selectable compatibility mode

After accepting the local cutover at `a0b5b4d48ce6b5f673622d7b7b70ca4b84ab3311`, the owner requested a temporary user-selectable compatibility path alongside the new default. When offered an exact pre-Flush rollback or Flush with P05, the owner selected **Flush with P05**.

- Default: post-submit Flush with no periodic fresh-render retries.
- Compatibility: keep the same post-submit Flush and restore the existing bounded P05 fresh-render/resubmission policy, with cached rehandoff off.
- Expose a persistent manual SteamVR-caption setting; do not introduce automatic failure detection or fallback.
- Preserve original caption expiry, current-only recovery, SELF/PEER independence, producer readiness and resource lifetime. Photo and desktop behavior remain unchanged.
- Verify both modes through the settings/application/native path, persistence across a fresh process, active-mode switching and current-only recovery. The previous no-retry result remains evidence for the default, not proof of this new setting.

This supersedes removal of P05 from every ordinary user-selectable path, not its removal from the default. The original checkpoint evidence below remains valid for its pinned builds. The [compatibility extension](#compatibility-extension-implementation-and-prepared-verification) is implemented and its paired live check completed on the [locally integrated candidate](#compatibility-live-verification); independent integrated and terminal review remain pending.

## Original no-retry checkpoint: implementation and decision

After a successful caption `SetOverlayTexture`, [the native caption runtime](../native/overlay/src/runtime.rs) calls `Flush` once on [the producing renderer's immediate context](../native/overlay/src/renderer/backend.rs), before handling visibility. The pre-submit GPU readiness check stays in place. Failed or preempted handoffs do not reach the added call. Flush is not a completion wait, permission to reuse a texture, or a display acknowledgment. Photo and desktop paths are unchanged.

The matched fixed-binary comparison found no additional protection from P05 in the tested cases. The implementation therefore removes periodic fresh renders and resubmissions from ordinary captions. [Python's generation start](../src/puripuly_heart/app/services/overlay/overlay_generation_start.py) no longer requests retry intent; it still refreshes the current scene and rearms original expiry deadlines on a new runtime. [The launcher](../src/puripuly_heart/core/overlay/process_runners.py) does not pass retry or experiment overrides on ordinary starts. [Native selection](../native/overlay/src/manifest.rs) defaults to `no_retry` and ignores retry-profile input unless cached rehandoff is explicitly selected. The cached rehandoff experiment remains available; readiness, cancellation, failure recovery, clear/Hide and lifetime rules remain in force. The bridge contract is unchanged.

### Integrated review: runtime ownership repair

Review of `3aa212fea763bec1182f4677b4036dc1016aade3` exercised the application owner, runtime handle and process manager with controlled spawn and process events (no OS child). The old automatic recovery launch could still be pending when a mode switch connected a new generation; the delayed child was later reaped. The reviewer’s offline reproduction is retained in `history://caption-453-integrated-review` (“Checking teardown branches offline”); it was not rerun to reconfirm it.

The runtime keeps the retiring manager and bridge while launch, late reaping or process cleanup is unsettled. A mode change in that window reports failed rather than connected or cleanly off. The stop path does not wait for an outstanding launch/reap to complete; a retry remains blocked until ownership settles. Even a completed reaper retains its child handle if termination did not confirm exit. A nonzero acknowledged exit fails the current mode switch with its diagnostic cause and retains the retiring owner; after confirmed settlement, explicit retry can release it and start a clean generation without erasing the old receipt. Presenter ingress, intended mode and caption lifetime are preserved during the failed switch. There is no automatic mode switch or public settings/protocol change.
