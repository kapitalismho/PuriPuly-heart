## Shared result contract

[ErrorDiagnostics](../src/puripuly_heart/core/messages.py) carries bounded underlying causes and explicit truncation. [The diagnostic owner](../src/puripuly_heart/core/diagnostics.py) owns construction, validation and canonical typed/JSON projections. Consumer-specific failure-field allowlists were removed from operation, chatbot and support views; unrelated capability/settings permission allowlists remain.

Mixed provider attempts retain their own status, category and validated technical fields. `provider.compound_failure` does not manufacture a common status or reinterpret a historical refusal. OpenRouter budget distinctions are accepted only from validated provider fields. Raw responses, exception prose, credentials, conversation content, audio, child output and personal paths are not technical evidence.

Failure construction precedes optional recording. A failed sink does not replace the originating failure or successful result. A diagnostic identity is not a promise that bounded history or file delivery retained it. Existing record/history/query limits remain; nested causes and result collections expose truncation rather than pretending omitted evidence was absent.

Successful fallback, unresolved cleanup, expected cancellation and terminal failure remain distinct. Translation results carry recovered failures separately from secondary cleanup evidence, including independent collection-omission flags. Configured provider/model choices are not relabeled as observed execution. Recognition probes retain recognition execution separately from the aggregate result when cleanup fails.

[Support bundles](../src/puripuly_heart/app/services/agent_chat/report.py) retain safe structured diagnostics and coverage. Missing optional logs are declared in missing-material metadata; no empty successful log is fabricated. Upload remains an explicit user-click operation, with the existing cancellation and exact-byte retry behavior.
