This is **richer upstream evidence outside the packaged adapter**, not a claim the product currently exposes all wire fields. Effective backend/base URL/version must be default Developer API v1beta; any override stops rather than silently inheriting capability. Final observation is 3 s, not a recognition-completion guarantee. No manual activity mode, B-prime, client_content turn completion or alternate model.

A finite successful trace can support a specific clock/control/content observation and can falsify a universal property with a concrete counterexample. It cannot establish universal one-fence-one-final, FIFO acoustic source association, no future duplicate/reorder/late final, fixed-word immutability, account concurrency/lifetime or billing minimum. ## Official contract versus observation

- [Qwen timestamps and reuse](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/real-time-speech-recognition-user-guide): sentence and word milliseconds are documented by default; words may represent word or character with separate punctuation. Legal socket reuse explicitly requires finish-task, matching task-finished, then run-task with a different task ID. Timestamp origin/reset and independent `fixed` finality are not established by these statements.
- [Qwen native server fields](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen-audio-asr-streaming-server-events): sentence_end defines finality; task completion and text completion are different. Provider-returned cumulative usage, if any, is retained as native evidence only.
- [Selected Gemini model](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe): input_transcription is authoritative final text; interim_input_transcription is speculative. Word timestamps and native live diarization are explicitly unsupported. Shared SDK optional word/speaker fields do not change the selected model contract.
- [Gemini Hybrid](https://ai.google.dev/gemini-api/docs/live-api/capabilities#hybrid-vad): audio_stream_end is an input/cache flush prompt; audio can resume. It does not supply an application fence-ID/capture-coverage contract.
- **Decisive normative ordering:** [Live server content reference](https://ai.google.dev/api/live#BidiGenerateContentServerContent), `inputTranscription`: **“The transcription is sent independently of the other server messages and there is no guaranteed ordering.”** Activity-offset semantics are stream-audio time in installed google-genai2.21.0 `types.py:20663–20682`, corroborated by [official JS VoiceActivity](https://googleapis.github.io/js-genai/release_docs/interfaces/types.VoiceActivity.html#audiooffset). VoiceActivity carries type+offset, not a matching final ID; Transcription has no activity reference. Thus receipt-order pairing to activity is **unsupported by the documented contract**, not a gap additional happy-path calls could settle.
