Existing owners remain authoritative: [architecture](architecture.md#stt), `core/audio/ownership.py`, `core/stt/backend.py`, `core/stt/scoped_normalizer.py` and `domain/recognition.py`.

### Strategy and attribution

1. **Presegmented input (P):** choose a not-yet-submitted PCM prefix using a causally available clear transfer; recognize it once. Keep the remainder ready without requiring a new VAD onset. A returned timestamp cannot justify the cut for that same decode. Do not decode a full parent and all children.
2. **Continuous timed final-source join (T):** keep input continuous; admit immutable, source-mapped contributions and join them to Nemotron evidence. A speaker boundary at 2.4 s learned at 3.0 s cannot retroactively seal a provider that already received 3.0 s at 2.4 s. Control, when lawful and necessary, flushes the provider's actual sent frontier.
3. **Conservative whole-span/unknown (C):** consume through the existing legal completion path. Whole-span speaker attribution needs verified enclosing source coverage and a single compatible speaker over that coverage. Otherwise retain text in gray. Gray is an attribution fallback, not permission to invent ownership or ordering. Untimed mixed text remains one unsplit source contribution.

Nemotron alone supplies speaker identity, including on Soniox. Native speaker IDs must not influence splitting, boundaries, palette, whole-span fallback or majority votes. Language changes are not speaker changes. A-to-A+B-to-A overlap is not two clear transfers: preserve ambiguous/overlapped words as unknown unless their own mapped coverage proves attribution. No forced alignment, per-speaker ASR, cloud presend hold or Gemini B-prime redesign.

### Source coordinates, context and identity


The [official NVIDIA integration guide](https://huggingface.co/nvidia/Nemotron-3-Diarization/blob/main/ASR_INTEGRATION_GUIDE.md), inspected 2026-10-06, explicitly permits conventional ASR on diarization-selected cuts for low-overlap audio and warns that an extracted range still contains overlapping voices. Its coupled per-speaker streaming examples are **not** the architecture selected here and do not certify the timing of any packaged PuriPuly ASR.
- Retain capture identity and the actual normalized sample rate. Each submitted payload needs ordered mappings between provider-input sample offsets and `AudioCaptureSpan` normalized ranges, including context-only and synthetic spans. `AudioCaptureSpan.slice_normalized` provides the existing capture projection (`core/audio/format.py:26–123`); a single request-start offset is insufficient after skipped silence or resampling.
- Convert provider milliseconds/seconds to provider-input samples using that request/stream's actual rate, then intersect each interval with the piecewise sent map. Do not map across missing speech, epochs, reversed intervals or uncovered time. Preserve explicit uncertainty at quantized boundaries rather than assigning a crossing token to the majority speaker. Point timestamps are not word intervals.
- Real onset pre-roll is eligible source only once. A previously owned hard-rollover prefix is context-only; synthetic silence has no source ownership. The existing hard rollover retains **300 ms** (`core/vad/gating.py:487–510,549–574`); this is not a new speaker-cut overlap recommendation. For a new batch speaker cut, default to disjoint content; do not add preceding-speaker speech as context when the untimed decoder cannot distinguish its text. Retain already captured subsequent speech as continuation.
- Distinguish activation, capture, provider/request and speaker epochs. Freeze the resolved route/model/backend, capability revision, settings and mapping with each request/result. A late result uses its originating route policy, never the currently selected Auto/Rolling member. Existing scope/epoch rejection remains in force.
- Deduplication uses contribution/event identity and source ranges, not text equality. Two distinct `no` contributions must survive; replay of the same contribution must not append. The existing normalizer can create contribution IDs and the consumption ledger can reconcile whole contributions and a terminal-only tail (`core/stt/backend.py:74–193`, `core/stt/scoped_normalizer.py:68–216`). It **does not support consuming an arbitrary subrange of one contribution**. Timed prefix implementation must add bounded interval consumption for routes that actually require it, without imposing that machinery on one-result batch routes.
- Keep text/language/provenance exact through normalization and terminal reconciliation. Never redivide translated text. An admitted immutable prefix stays immutable; a terminal snapshot must identify its already consumed pieces and retain its previously unconsumed tail. Missing provenance means no new timed prefix admission, not string-based tail guessing.

### Boundary → source progress, not transport retirement

For each source/control scope, keep a closure identity and the sent frontier it covers. Record boundary source position, evidence-ready time, submitted frontier, final-source availability and publication separately.

| State at a known boundary | Action |
| --- | --- |
| Unsubmitted batch prefix, clear transfer, valid retained map | Seal/select the prefix once and dispatch one decode; retain continuation. |
| Immutable timed text already covers the prefix | Admit its unconsumed contributions; no finalize is needed. |
| Final text missing and this row permits nonterminal provider input control | Send the row's control once at the actual sent frontier after its minimum/serialization rules; wait for its defined evidence, not merely an ACK. |
| Final text missing but control semantics unverified/unsupported | Preserve normal endpoint/hardcut completion, unresolved text and gray attribution; do not invent a control. |
| Text exists but provenance/order is unresolved, or translation execution is full | Resolve/bound that ownership or execution state; **do not send another finalize** solely for it. |
| Duplicate boundary/control request or ACK | Reuse the existing closure state; no extra decode, finalize, source, translation or TTL renewal. |
| Empty result, disconnect, timeout or failed control | Record the appropriate empty/failure/uncertain outcome. Never promote ACK, input bookkeeping or provisional text to immutable final coverage. |

An ACK establishes only the acknowledged control. Input-terminal establishes the local input lifecycle, not server recognition completion. Final text establishes only its documented contribution, not arbitrary capture coverage. Provider-specific task termination may end that task without closing a reusable transport; speaker changes never mandate a new connection. Preserve 60 s source/VAD-idle retirement, pending-owned-input drain, and provider maximum lifetimes. Keepalive/returned text are not source activity.

### Short speech, natural end and safety

The former **one-second speaker-cut minimum is rejected as a universal source-unit floor**. The inspected baseline contains no common implemented speaker-cut guard to remove; #211 identifies the historical policy to evaluate. Natural short negations, corrections, numbers and interrupted speech remain eligible at the existing endpoint. This does not waive a provider's real minimum audio or commit spacing.

Preserve `ListenDeliveryController.HARD_LIMIT_S = 6.0`, existing natural completion and its continuation behavior (`core/audio/listen_delivery.py:38–47,119–132,163–211`). A speaker cut is internal to the enclosing display grouping; it does not reset or replace that safety obligation. No route gets silence fabricated as speaker evidence or short speech discarded to save calls. Route-specific controls below retain documented constraints; lowering a transport minimum requires an authorized bounded server regression probe, not this report's synthetic fixtures.
