# Phase 1 model and artifact registry

All model artifacts used by Phase 1 are **external to this repository**. They
are identified here by exact revision, SHA-256, and size. `registry.json` is
generated by `provenance.py` and is the machine-readable authority; this file
documents provenance and redistribution rules.

## LS-EEND

- Official implementation: Audio-WestlakeU/FS-EEND, revision
  `adcdde1327bc731cc4e718aa009b8d78317388e5` (MIT license).
- Third-party stateful ONNX export: `GradientDescent2718/LS-EEND-ONNX` on
  Hugging Face, revision `cc40a1e1242c148fbbc15c132e43b8ac15056e53` (MIT).
  Four variants: `L-AMI`, `L-CALLHOME`, `L-DIHARD-II`, `L-DIHARD-III`.
- Each variant ships `ls_eend_*_step.onnx` (opset 17, non-quantized step
  model) plus a sidecar JSON declaring state tensor shapes and frontend
  parameters. Exact hashes and sizes are in `registry.json`.
- The ONNX weights were exported from the FS-EEND LS-EEND code path. The
  third-party repository does **not** state which official checkpoint file
  hash each ONNX file was exported from; we therefore verified weights by
  numerical parity against the official PyTorch checkpoints (ami.ckpt,
  ch.ckpt, dih2.ckpt, dih3.ckpt, downloaded from the official Google Drive
  links in the FS-EEND README) on a fixed parity set. Parity result: max
  absolute probability error <= 2.7e-6 across all four variants (see
  `results/parity_research.json`).
- Important frontend finding: the official FS-EEND feature code
  (`datasets/feature.py::stft`) computes a **256-point FFT** (fft_size = 1 <<
  (200 - 1).bit_length()), despite `n_fft: 1024` appearing in the yaml
  configs and in the ONNX sidecar metadata. The third-party streaming
  example extractor uses 1024-point FFT, which deviates from the official
  reference (measured feature deviation up to ~10 on the parity set; the
  repo's own stream-vs-offline comparison reported ~1e-5 probability error).
  Phase 1 uses the official 256-point semantics.
- Dataset licensing (AMI, CALLHOME, DIHARD II/III) governs the training data;
  redistribution of these ONNX exports is MIT per the third-party repo.

## ERes2NetV2

- Official artifact (standard): ModelScope `iic/speech_eres2netv2_sv_zh-cn_16k-common`,
  revision `1cf80d41fb3435bd3d8df185b5c423333b2db42a`,
  file `pretrained_eres2netv2.ckpt` (Apache-2.0), embedding size 192,
  baseWidth 26 / scale 2 / expansion 2, 80-dim kaldi fbank frontend at 16 kHz.
- Official artifact (w24s4ep4): ModelScope `iic/speech_eres2netv2w24s4ep4_sv_zh-cn_16k-common`,
  revision `d41a54156a6216b4c7611447be0548e4b0afb1ba`,
  file `pretrained_eres2netv2w24s4ep4.ckpt` (Apache-2.0), embedding size 192,
  baseWidth 24 / scale 4 / expansion 4. Resolved unambiguously from the
  official 3D-Speaker release notes (revision `065629c313eaf1a01c65c640c46d77e61e9607b4`).
- Both are PyTorch Lightning checkpoints; we exported each to ONNX (opset 17,
  dynamic time axis, `fbank` (1, T, 80) -> `embedding` (1, 192)) with the
  official 3D-Speaker model class. Torch-vs-ONNX embedding cosine >= 0.9999999
  on the parity set. The ONNX files are not committed; hashes of the exported
  files are in `registry.json` (re-exportable with the documented research
  environment).
- Redistribution: Apache-2.0 (3D-Speaker code and ModelScope model cards).

## Parity set

- the three committed Phase 0 golden wavs (deterministic synthetic);
- three ModelScope example wavs (`speaker1_a_cn_16k.wav`,

  `experiments/speaker_turn_boundary/run_parity.py::MODELSCOPE_EXAMPLE_WAVS`.

```powershell

git clone --depth 1 https://github.com/Audio-WestlakeU/FS-EEND <cache>/FS-EEND
git clone --depth 1 https://github.com/modelscope/3D-Speaker <cache>/3D-Speaker
# official FS-EEND checkpoints via the Google Drive ids in provenance.py
# ModelScope models via: python -m modelscope download ... (see provenance.py)
```
