## Root cause (corrected - v3's conv hypothesis was wrong)

Flushed pipeline logging (`TRANSCRIBE_VK_LOG_PIPELINE`, since removed; logs in `results_driver_bug/pipe_log_7s_stderr.txt`) proves standard `CONV_2D` nodes never dispatch on Vulkan - the scheduler keeps them on CPU - so no standard-conv shader is involved. 32 compiles started, 31 finished; the unfinished one is `mul_mat_vec_f16_f32_f32`. The vec path triggers for matmuls with N<=8 (`mul_mat_vec_max_cols`, `ggml-vulkan.cpp:9262`); tails with T_enc=5 (M=36/40: 7/8/20 s) compile it for the first time and the AMD compiler (amdvlk64.dll 9.2.10.388, driver 2.0.388, api 1.4.344, 7900 XTX 0x744c) AVs. Every other observed N (3,4,6,9-14) compiles fine.
