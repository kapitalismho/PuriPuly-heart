`VAD frontier` uses exactly `input_count/input_rate − floor(output_count/512)*512/16000` per callback; the callback emitting zero samples still ages the last completed VAD frontier. Consequently neither pending delay nor 32-ms block assembly can be added arithmetically to the measured joint age. First output is continuous-stream startup only. Every final count is exactly 48,000, and flush is only at finite end; no per-utterance reset. Relative to the historical Linux/python-soxr 1.0.0 advisory, matching 48 k/480 MQ 21.406/37.625 ms and 44.1 k/441 MQ 23.125/41.125 ms pending results is an empirical coincidence, **not** an assertion of version interchangeability.

A separate 3-second fixed *generated voiced-tone envelope* (two voiced intervals, one pause; **not human representative speech**) fed `CaptureMappedStreamingResampler` at each actual callback size then `VadGating.process_owned_chunk`, splitting mapped spans via production `_capture_prefix` at each 512-sample block. Every observed block carried exactly 512 mapped samples; the mapped VAD frontier ages matched the zero-grid p50 ages (48 k/480 36 ms; 44.1 k/441 40 ms), and 48,000 normalized samples were accounted by finite flush. Final MQ tails were 194 at 48 k and 302 at 44.1 k, and bypass had zero. Abort emitted zero tail and returned outstanding owned spans (one at resampled rates, none in bypass); unknown epoch discontinuity discarded the pending previous epoch and reset streaming state. Stereo mono-first samples matched an independent average-then-stream path numerically for the generated fixture. The amplitude engine is **not** Silero; these checks establish source mapping/continuity/tail and interface timing only. Production `run_audio_vad_loop` uses the same mapped normalizer before VAD, and #134 C3 finite/abort rules remain unchanged.
