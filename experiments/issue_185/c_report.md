## Reproduction and status

`c_h_probe.py` drives the real `LocalGpuSTTBackend` scoped session, `SharedGpuASRRuntime`, WAV writer, owned thread, and worker client port; only the Vulkan/IPC worker response is a local stub. On Windows, execute with the existing venv: `python -c "import sys,runpy;sys.path.insert(0,'src');runpy.run_path('experiments/issue_185/c_h_probe.py',run_name='__main__')"` (or set `PYTHONPATH=src`). Its gates intercept `Path.unlink` in the owned cleanup thread and check WAV bytes against the prechange quantization chain. Saved runs: `c_before.json` (baseline code, before probe's 20 ms observation hold was added) and `c_after.json` (changed code); Python 3.14.7, NumPy 2.5.1, Windows 11 22631, 16,002 samples, one request, fixed input. Both files describe one run, **not** latency distributions. The after gate held deletion for 20 ms and the transcript was already delivered while held; before the transcript was not delivered while deletion was held. Do not compare the two `delete_gate_to_result_ms` numbers as a speedup: the observation protocol changed to allow the event loop to propagate the result while the gate was held. This is causal ordering proof, not an end-to-end latency gain.

The dispatcher fences current worker generation, channel, discard reason, and outstanding future before settling the valid response. It settles before scheduling WAV unlink. The sole runtime owns at most one outstanding cleanup task; the next dequeue waits for it, so a stuck deletion imposes bounded backpressure rather than accumulating WAVs. Shutdown, worker failure, channel-cancel escalation, and decode recovery drain it before temporary-directory cleanup. The worker has finished using that path before unlink starts. The scoped adapter's native request task remains owned until its response; closing a channel still invalidates publication. A failed unlink emits a failure diagnostic and does not replace the already valid transcript. If the channel remains active, the runtime faults before dispatching a successor (queued jobs retire as failures) and drains the worker and residual directory; this prevents repeated failed deletions from accumulating unbounded files. Existing worker/model admission and one-inference scheduling were not changed.

After-probe diagnostic (seconds, mock worker and filesystem; **not Vulkan inference**): `gpu_queue_wait=0.0000130` (actual enqueue-to-dequeue), `speech_end_to_dequeue=0.0001146`, `wav_stage=0.0024929`, `worker_request_to_response=0.0037911`, `worker_response_to_transcript_publish=0.0000070`, and `file_cleanup=0.0217921` **including the artificial gate**. `published=true` records that the fenced result was actually settled; rejected transcripts have no publish interval.
